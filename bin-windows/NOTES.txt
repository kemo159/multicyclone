Built with CUDA 13.1 (nvcc V13.1.115) + MSVC 14.44, sm_120 only (RTX 50-series).

Includes the per-thread tail fix: per_thread_cnt is rounded up to a multiple of
the batch size B. Binaries built before 2026-08-25 rounded by a whole B, which
left every thread with 0 < rem < B forever -- the kernel's `rem >= B` guard
could not consume it while `rem != 0` kept setting d_any_left, so the host
relaunched an empty kernel indefinitely, pinned at 100%.

For any other GPU, build from source - see README.md.

Also supports checkpoint/resume: a run stopped with Ctrl+C or --seconds writes
cyclone_checkpoint.txt, and re-running the same command with --resume continues
from there. --resume refuses to run unless the target, --range, --grid, --slices,
--tpb and GPU set all match what the checkpoint was written under.

New in v3.1: --autosavetimer SECONDS rewrites the checkpoint every N seconds
while the search keeps running, so a crash, a power cut or kill -9 costs at most
one interval instead of the whole run. Ctrl+C and --seconds already saved on the
way out; this covers the stops that never get the chance. Recovery is the same
--resume path, and the checkpoint is written to a temp file and renamed over the
target so a crash mid-save cannot truncate the previous good one.

New in v3.2: fixed four correctness bugs in the AVX2 CPU worker (cpu_avx2/Cyclone.cpp,
used by --cpu-auto/--cpu-percent and the standalone CPU build). (1) A batch's center
key (offset 0, and offset 255 whenever that key is <= 255) hit an out-of-bounds
GTable read / point-doubling degeneracy in the chord-addition shortcut and was
silently skipped instead of checked. (2) The last batch of each thread's range
could stop up to 254 keys short of the requested end instead of covering it fully.
(3) An accepted match was never checked against the overall requested range, so a
batch's +/-255 spread could report a key technically outside --range. (4) The
degenerate-slot placeholder point could coincide with a real target hash and get
reported as a false positive, overwriting an already-found correct result. All four
were found by an exhaustive coverage audit (2,734 cases, 0 misses/errors after the
fix) and do not affect the GPU-side search path.
